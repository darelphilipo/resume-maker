# CONTEXT.md — Working Memory for Autonomous Runs

This file is the durable memory between autonomous sessions. `TASKS.md` is the
queue; this file is the **why** and the **gotchas** that are expensive to
rediscover.

## How to use this file

1. **Read it before starting a task.** `AGENTS.md` → `TASKS.md` → `CONTEXT.md`.
2. **Before you finish**, append one entry to *Session Log* below:
   - the task you attempted,
   - what actually changed (files),
   - anything a future run must know: new constraints, dead ends, hidden
     coupling, surprising test behaviour.
3. **Keep `README.md` current.** If the task changes anything a user can see or
   do, update the **Key features** tour in plain user language. The README is
   not a changelog: no dates, run logs, or file lists there.
4. **Promote, don't duplicate.** If a durable fact belongs in *Decisions &
   Gotchas*, add it there and keep the session entry short.
5. Keep *Session Log* to the **10 most recent** entries; delete the oldest.
6. Never write secrets, tokens, API keys, or personal user data here.

## Non-negotiable constraints

- **Static export only.** `next.config.ts` sets `output: "export"`. No server
  actions, no route handlers, no middleware, no ISR, no `next/image`
  optimization. Anything that needs a server is out of scope.
- **Zero backend, zero accounts.** All persistence is client-side (Dexie/IndexedDB).
  No network calls for user data. Privacy is the product.
- **Mobile-first.** Touch is the primary input; desktop is the enhancement.
  Every change must be verified at a phone viewport, not just 1440px.
- **`basePath` awareness.** Deployed under `/resume-maker`. Never hardcode
  absolute asset or route paths — respect `PAGES_BASE_PATH`.
- **Free forever.** No paywalls, watermarks, sign-up gates, or "trial" patterns.
- Keep `AGENTS.md` intact — the `nextjs-agent-rules` block is regenerated by
  `next dev` and removing it just recreates an uncommitted diff.

## Decisions & gotchas

1. **The mobile shell owns its own scroll.** `EditorWorkspace` is
   `flex h-dvh flex-col overflow-hidden`; `<main>` is the only scroll container
   and `MobileBottomNav` is **in normal flow** (never `position: fixed`, which
   anchors to the layout viewport and disappears behind mobile browser chrome).
   Use `min-h-dvh`, not `min-h-screen`.
2. **`viewport-fit=cover` is required** (`src/app/layout.tsx` `viewport` export)
   or `env(safe-area-inset-*)` silently resolves to 0.
3. **Canvas gestures differ by pointer type.** Pinch is enabled everywhere.
   On coarse pointers `panning` stays disabled so a one-finger swipe scrolls
   the page while the resume is fitted; `touch-action: pan-y` reinforces that.
   Once the preview is zoomed, `TouchPanCanvas` takes over both axes and the
   canvas switches to `touch-action: none` (see #26). Desktop wheel/pinch/drag
   must stay untouched. For touch-only UI, prefer Tailwind's built-in
   `pointer-coarse:` variant (Tailwind 4) over JS `matchMedia`, so there is no
   hydration flicker.
4. **PDF filename comes from `document.title`.** There is no HTTP response in a
   static export, so title is the only lever. Format:
   `{name}-{headline}-{YYYY-MM-DD}-resume`, lowercase-kebab, local date. A
   1200 ms grace on coarse pointers keeps the title alive after `afterprint`.
5. **Wheel zoom is intercept-and-scale, and modifier-gated** (`src/lib/zoom/`).
   Only Ctrl/⌘ + wheel zooms (`isZoomWheel` in `wheelZoom.ts`): browsers
   synthesize `ctrlKey` on trackpad pinch, while a plain wheel or two-finger
   scroll must reach the page scroller untouched so multi-page resumes scroll
   natively. `WheelZoom` returns before `preventDefault()` for every other
   wheel event.
6. **Pagination measures real DOM.** Height comes from `MeasureLayer`; changing
   print CSS or template line-height changes page counts and breaks snapshots.
7. **`npm ci` is the CI contract.** Editing `package.json` without a matching
   `package-lock.json` update fails the build. Run `npm install <pkg>` so both
   change together.
8. **Import fixtures share IDs.** Importing a resume whose items reuse one `id`
   produces React duplicate-key console errors. When generating fixtures, give
   every item a distinct `id`.
9. **Date fields store `YYYY-MM`.** Shared helpers live in
   `src/lib/date/month.ts` (`formatMonth`, `toMonthValue`, `parseMonthInput`);
   `DateRange` re-exports `formatMonth` for compatibility. Every dated form now
   uses the shared `MonthSelect` (a Jan–Dec `<select>` plus a four-digit numeric
   year input, both `min-h-11` and `bg-surface`): native `<input type="month">`
   is deliberately gone because its year scroller is browser-dependent (a modal
   wheel on phones). `MonthSelect` commits only a complete `YYYY-MM`, keeps
   partial drafts local, and clears on an empty month/year. Experience and
   Education end dates own the **Present** toggle and disable the picker while
   current; `GenericSectionForm` pairs Volunteer's `current` field the same way
   (its standalone checkbox is skipped). Projects has no `current` flag. Keep
   every future date field on `MonthSelect`; `MonthInput` remains the compact
   free-text fallback if a genuinely narrow cell needs one.
10. **Fit-to-one-page is persisted in `metadata.page.fitScale`** (0.5–1,
    default 1). The scale is applied to the existing Onyx `--resume-*`
    variables and to `gapPx` so preview, measurement, and print agree.
    `usePageLayout` returns the next safe target via `computeFitScale`;
    forced `startOnNewPage` sections disable it. Keep `MeasureLayer` in sync:
    its inline `font-size` overrides `.onyx`, so scaling only the CSS variable
    leaves measured heights (and pagination) unchanged.
11. **ATS text is a parallel renderer, not DOM scraping.**
    `src/lib/ats/atsText.ts` re-implements the visibility rules, field order,
    date formatting, and section order used by `SectionRenderer`, `HeaderSlot`,
    and `usePageLayout` (first layout page `main` + `sidebar`). Any change to
    what those components render must be mirrored there or the ATS preview
    silently drifts from the PDF. `basics.workAuth` is part of that contract:
    the header prints it as a tag between location and website, so `contactLine`
    must push it in the same position. Skills are category + comma-separated
    keywords; the 1–5 level stays in the schema only so imported JSON parses,
    and `SkillEntry` no longer renders a proficiency indicator (Languages still
    do).
12. **JD keyword matching runs on the ATS text, locally.** The matcher in
    `src/lib/keywords/jdMatch.ts` extracts lowercase tokens from the pasted
    posting (drops boilerplate stopwords, ranks by frequency, tolerates trailing
    dots and simple plurals) and compares them with `buildAtsText(doc)`. Hidden
    or empty sections therefore do not count as matches. Keep it pure and
    client-side: no network calls, no AI, no persistence of the job description.
13. **`SectionList` tucks empty optional sections.** Awards, Languages,
    Interests, Volunteer, Publications, and References are hidden from the
    default list while empty; `+ Add optional section` reveals and expands one.
    A row stays visible once it has items or has been hidden by the user. The
    reveal state is session-local, so an added-but-still-empty section re-tucks
    on reload. Move actions run against visible rows and preserve tucked slots
    in `layout.pages[0].main`, so a Move click is never absorbed by a hidden
    row.
14. **Role presets must follow the current renderers.** `src/lib/presets/archetypes.ts`
    builds the launcher samples. Skills are three `skillCategory(name, keywords)`
    rows per role (no proficiency bars); `level` stays `0` only because
    `SkillItemSchema` still requires the field for import compatibility. The ATS
    view prints a category name on its own line followed by comma-separated
    keywords, so keep sample keyword lists comma-safe (no commas inside a
    keyword).
15. **`opencode.json` is human-owned.** Its `permission.edit` denies
    `.github/workflows/*` and `opencode.json` itself, so an autonomous run
    cannot change the autopilot workflow or OpenCode config. Ask the human or
    use a temporary `.opencode/opencode.json` override.
16. **Custom sections live in two places.** Adding one must append its `id` to
    `metadata.layout.pages[0].main` (the only page `usePageLayout` reads) as
    well as to `customSections`; deleting one must strip the id from every
    page's `main` and `sidebar` or stale layout entries linger. Custom titles
    are edited inside `CustomSectionForm`; standard headings use the debounced
    `SectionHeadingInput` in `SectionList`. An empty heading intentionally
    hides that section's heading in the PDF.
17. **Contact labels are derived, not hand-authored.** `src/lib/links/contactLinks.ts`
    owns both heuristics: `detectProfileLink` maps ~25 known profile hosts to
    `{ network, icon, username }` (unknown hosts return `null` so a personal
    site never invents a network), and `websiteLabelFromUrl` strips protocol,
    `www.`, query, hash, and trailing slashes for the header label. The profile
    `Icon` descriptor stays in `GENERIC_SECTION_FIELDS` with `hidden: true` so
    imported icons survive round-trips without asking the user; any new
    non-rendered field should use the same pass-through. `BasicsForm` preserves
    an imported custom website label until the URL itself changes.
18. **Paste-to-parse is a third importer.** `src/lib/import/pasteResume.ts`
    maps plain text into a `ResumeDocument` using a section-alias table; content
    under an unrecognised heading folds into the previous section, so add every
    new standard heading alias there when a section is introduced. It emits
    escaped `<p>`/`<ul>` rich text, and `Launcher` still runs
    `sanitizeResumeDocument` before `importResume`. Dates normalize to
    `YYYY-MM` (year-only ranges use `-01` for the start and `-12` for the end).
    Keep the parser pure and client-side: no network calls, no AI, and no
    persistence of the pasted text.
19. **The print reminder is a tooltip, not a layout row.** `PrintTriggerButton`
    keeps the “Headers and footers” message in an absolutely positioned
    `role="tooltip"` bubble so the print control stays the same 44px height as
    Undo/Redo/JSON. Fine pointers show it on `pointer-fine` hover/focus; coarse
    pointers get a `pointer-coarse` info button that toggles `aria-expanded`.
    Closing on outside `pointerdown`, blur, and Escape is deliberate: mobile
    Safari does not always focus buttons on tap. The header title uses
    `basis-24` so the action group wraps as a unit and stays right-aligned
    rather than squeezing the resume name.
20. **PDF import is lazy and workerless.** `src/lib/import/pdfResume.ts`
    dynamically imports `pdfjs-dist` and `pdfjs-dist/build/pdf.worker.mjs`.
    Importing the worker module registers `globalThis.pdfjsWorker`, so PDF.js
    uses its in-thread fake worker instead of fetching a separate worker asset.
    That keeps the static export self-contained, offline-safe, and independent
    of `basePath`. Never statically import PDF.js from `Launcher` or the editor;
    the chunk is large and only needed after a PDF is chosen. Text items are
    grouped by Y (±2.5 pt), ordered by X, joined without a space when the visual
    gap is ≤1.5 pt, and separated by a blank line when the gap exceeds 1.6× the
    page's median line gap. The reconstructed text is fed straight into
    `parsePastedResume`, so any parser fix benefits both import paths. Two-column
    PDFs can interleave columns; this is a text heuristic, not a geometric
    layout parser.
21. **JSON is a backup path, not a starting point.** The `/` launcher keeps
    three primary cards: Paste, Upload a PDF, and Start from scratch. JSON
    restore lives in a collapsed `Backup & Restore` disclosure at the bottom
    (`aria-expanded` + `aria-controls`; the panel is a `<div>`, not a
    `<section>`, so `getAllByRole("region")` still counts only the primary
    cards). Export stays in the editor header (`ExportJsonButton`), and the
    disclosure copy points users there. PDF upload now has its own input and
    error state; do not fold JSON back into the primary file picker.
22. **Action-verb helpers are opt-in and insert plain text.** `RichTextField`'s
    `actionHelpers` prop renders the `[Action] + [What] + [Result by X%]` prompt
    and four 44px chips (Built, Reduced, Led, Automated). A chip inserts the verb
    plus a trailing space at the cursor via TipTap `insertContent`; it does not
    wrap the current selection or add formatting. Only achievement-style fields
    (Experience and Projects descriptions) pass the prop — Summary, award
    notes, and reference notes stay prose-only. Keep the chips local and
    client-side: no AI suggestions, prompts, or network calls.
23. **The home page is a landing page, not a bare form.** `src/app/page.tsx`
    owns the only `h1`, the `Resume Maker` wordmark; the e2e a11y and page tests
    look that heading up by name, so the value proposition stays an `h2`. The
    `Launcher` keeps exactly three entry `<section>`s labelled by their card
    headings, so `getAllByRole("region")` still returns three. Trust promises
    stay a `ul[aria-label="Resume Maker promises"]` of three `li` items, but
    they are one compact nowrap line, not three bordered capsules: per-phrase
    `whitespace-nowrap` labels never break mid-phrase, dot separators and icons
    appear only at `sm+`, and items have no capsule padding or border. Keep the
    separators `aria-hidden`; the old inline `·` text made screen readers read
    "100% Free · No Sign-Up". `page.tsx` is
    a server component, so do not import Phosphor icons there (they call
    `useContext`); the brand mark is an inline SVG.
24. **The warm paper/navy theme is token-driven.** `src/app/globals.css` owns
    `--brand-*` (`background` #f5f3ee, `surface` white, `surface-muted` #fbfaf7,
    `line` #e3ddd2, `muted` #5b6a7a, `primary` #1b3a57) and exposes them to
    Tailwind as `bg-background`, `bg-surface`, `border-line`, `text-muted`, and
    `text-primary`. Use those tokens for app chrome instead of hardcoded hex or
    heavy `black/10` borders so `/` and `/editor` stay in sync. The printed
    resume is a separate surface: `.resume-page` is always white, the Onyx
    template injects its own `metadata.design` colors, and `print.css` forces
    `body` white. Do not put editor chrome colors on resume surfaces.
25. **The editor header is one nowrap row.** The old `basis-24` title forced
    the action group onto a second line at phone width. The title now shrinks
    (`min-w-0 flex-1`) while the actions stay `flex-nowrap`: icon-only Undo,
    Redo, JSON, and Save PDF are `min-w-10` (44px tall) on mobile and `sm:min-w-11`,
    the JSON label only appears from `sm`, the print info button is `min-w-8` on
    coarse pointers, and the header row itself is `flex-nowrap`. Keep those
    rules if you add another header action — a label or an extra 44px control
    eats the resume name at 375px.
26. **Preview zoom is pinch-first with free two-axis panning.**
    `src/lib/zoom/canvasGestures.ts` keeps `pinch` enabled at every pointer
    size, disables `panning` only on coarse pointers, and pairs that with
    `canvasTouchAction`: `pan-y` at the fit scale so one finger still scrolls
    the page (see #3), `none` once zoomed so the browser cannot begin a vertical
    page scroll before the canvas claims the drag. `TouchPanCanvas` (renamed
    from `HorizontalTouchPan`) listens on the preview pane (the library
    `stopPropagation()`s moves it handles), waits for `TOUCH_AXIS_SLOP_PX`, then
    pans **both** `deltaX` and `deltaY` through `panBy`. The zoomed canvas is
    clipped inside a fixed-height transform wrapper, so vertical panning is the
    only way to reach the bottom of the page; page scrolling returns as soon as
    the user resets to fit. Panning is gated by `isPreviewZoomed`. Because
    `touch-action: none` also locks out native scrolling, vertical drags are
    clamped to the library's `instance.bounds`: once the canvas hits its top or
    bottom edge, `resolveVerticalPanHandoff` hands the leftover delta to
    `scrollPageBy` (`src/lib/zoom/touchScroll.ts`), which scrolls the nearest
    scrolling ancestor (`<main>` on mobile). Dragging down at the canvas top
    therefore scrolls the editor back up to the preview toolbar and Reset
    instead of stranding them off-screen on a multi-page resume. There is
    **no zoom/pan toolbar**: page count plus the `Reset fit` / `CanvasResetButton`
    pills sit in a normal-flow `[data-canvas-toolbar]` row *above*
    `<TransformWrapper>` (see #36), never floating over the paper. Because the
    toolbar is outside the wrapper, `LiveCanvasViewport` mirrors the zoomed bit
    through `onTransform` and resets with a `ReactZoomPanPinchContentRef`;
    `CanvasResetButton` is now a props-driven pill. `useControls().state` is
    mutated in place and does not trigger renders, so do not read `state.scale`
    in render for visibility. Wheel zoom and drag panning on fine pointers are
    unchanged. `HorizontalTouchPan.tsx` is now a deprecated re-export shim, and
    the old `CanvasControls` toolbar is superseded; delete both in a run with
    file-delete access.
27. **Editor inputs read as white fields, and hints never fade below AA.**
    `RichTextField` is a `bg-surface` shell with a `bg-surface-muted` toolbar
    strip and a white `.tiptap` area; `TextInput`/`MonthInput` share the
    `INPUT_CLASS` white surface, and `EntryCard` is tinted (`bg-surface-muted`)
    so nested white inputs stand out. Placeholders use `text-muted` (#5b6a7a,
    5.5:1 on white) plus `placeholder:opacity-100` because Firefox dims
    placeholders by default. Never use `opacity-60` for hint copy on white — it
    drops below 4.5:1; use `text-muted`. The empty `.tiptap` placeholder is
    `var(--brand-muted)` for the same reason.
28. **Only Preview and Design stick at `lg`.** `panelClass()` in
    `EditorWorkspace` takes `{ sticky: true }` for `#panel-preview` and
    `#panel-design`, adding `lg:sticky lg:top-[var(--header-height,3.5rem)]
    lg:max-h-[calc(100dvh-4rem)] lg:overflow-y-auto lg:overscroll-contain`.
    Content stays in normal page flow so the other two `top-0`-sticky columns
    have something to scroll past. Sticky needs the existing `lg:items-start` on
    `<main>` (otherwise grid stretch kills it) and `lg:h-auto lg:overflow-visible`
    on the shell (on mobile `<main>` must stay the only scroll container, see
    #1). `--header-height` is not defined yet, so the `3.5rem` fallback matches
    the one-row header; update it if the header ever grows. The preview column's
    scrollbar is the only way to wheel-scroll it over the paper: `WheelZoom`
    still `preventDefault()`s wheel events to zoom.
29. **A section has one editor at a time.** `EditorWorkspace` passes
    `openSectionId={drawerSection?.id}` to `SectionList`; the expanded row
    skips its inline `<SectionForm>` for that id while the drawer is open.
    Rendering both copies mounted two TipTap editors per rich-text field (24
    editors for a 12-entry Experience resume) and duplicated entry field ids,
    which made the drawer stall for seconds on phones. The inline form returns
    when the drawer closes. For the same reason, `RichTextField` memoizes its
    `extensions` and `editorProps`: `@tiptap/react`'s `useEditor` compares
    options by identity on every render and calls `setOptions` (rebinding the
    ProseMirror view) when they differ, so inline-constructed object arrays
    reconfigured every editor on every transaction (`shouldRerenderOnTransaction`).
30. **Drawer triggers belong to vaul, not a bare `onClick`.** `EntryDrawer`
    accepts an optional `trigger: ReactNode` rendered as
    `<Drawer.Trigger asChild>` inside `Drawer.Root`. vaul/Radix then own the
    open toggle and set `aria-haspopup="dialog"`, `aria-expanded`, and
    `aria-controls` pointing at the portalled content, so the drawer opens
    identically on desktop and touch. `JdMatchDrawer` passes its button this
    way instead of calling `setOpen(true)` itself. `Drawer.Trigger` is Radix's
    primitive (no pointer-capture handler), so `userEvent.click` on it is safe
    in jsdom; only children *inside* `Drawer.Content` need `fireEvent.click`.
31. **The 22rem Content sidebar is the layout budget.** Inside the
    `lg:grid-cols-[minmax(0,22rem)_...]` panel, eight `RichTextField` toolbar
    buttons plus gaps are wider than the usable cell (≈250px after the card,
    entry-card, and toolbar padding), so the formatting row is `flex flex-wrap`
    with `min-h-9 min-w-9 shrink-0` buttons on fine pointers and
    `pointer-coarse:min-h-11 pointer-coarse:min-w-11` on touch. Wrapping is
    deliberate: the old `flex-nowrap overflow-x-auto` row put Undo/Redo behind an
    invisible horizontal scroll strip, so users could not see that Redo existed.
    `EntryActions` still fits on one line and keeps `flex-nowrap gap-1`. All
    shared inputs carry `min-w-0` (`INPUT_CLASS` plus the `TextInput` /
    `MonthInput` wrapper) so a control's intrinsic width can never force the
    narrow column sideways. Paper-size cards need an explicit `htmlFor`/`id`
    pair plus `w-full` — a bare `<label><input/></label>` does not reliably
    forward a click on the detail `<span>` to the radio in every browser.
32. **Six templates, one rendering contract.** `src/templates/registry.ts`
    registers all six `TEMPLATE_IDS` with `TemplateDefinition` metadata
    (`label`, `description`, `columns`, `atsSafe`, optional `badge`) and exports
    an ordered `TEMPLATE_LIST` for the picker. Five single-column layouts reuse
    `OnyxTemplate`'s DOM, adding only a root class (`onyx--ivy`, `--accent`,
    `--compact`, `--skills-first`, `--studio`) styled by prefixed global CSS in
    `variants/` and `studio/`; `buildTemplateThemeStyle` in
    `shared/templateTheme.ts` is the one source of the resume CSS variables, so
    preview, measurement and print stay aligned. `atsSafe === (columns === 1)`
    by design, and `TemplateBadge` renders **ATS-Safe** or the two-column
    layout's **Best for direct/human review** label. Two traps: `HeaderSlot`
    sets inline styles and the theme variables are inline on the root, so a
    variant class cannot override them without `!important` — style descendants
    and derived properties instead. The Studio Sidebar splits sections by
    `STUDIO_SIDEBAR_SECTION_IDS`, so its visual order differs from the canonical
    order used by `atsText.ts` and `MeasureLayer`; treat that as a known
    limitation until the measure layer is template-aware.

33. **Preview chrome is sticky, and hand-off scroll eases in.** The
    `Visual`/`ATS text` row in `EditorWorkspace` is `sticky top-0 z-20
    min-h-14`, and the overflow banner + page-count/Reset toolbar are grouped
    in `PreviewChrome` (`[data-preview-header]`, `sticky top-14 z-10`) inside
    `LiveCanvasViewport`. `top-14` (56px) is the mode row height — keep the two
    offsets in sync. The viewport root uses `overflow-clip`, **not**
    `overflow-hidden`: `hidden` creates a scroll container, which would pin the
    sticky child to that non-scrolling box and break stickiness. `CanvasToolbar`
    (with `CanvasResetButton`) lives inside `TransformWrapper` so it keeps
    transform context; the wrapper is a context-only provider with no DOM node,
    so wrapping extra siblings is safe. Both headers stay in normal flow, so
    Page 1 starts below them instead of being covered at rest. The vertical
    pan-to-scroll hand-off now calls `dampHandoffScroll` (`HANDOFF_RAMP_MOVES =
    4`): the page-scroller contribution ramps in over the first four at-bound
    touches instead of snapping by the full leftover delta on contact; any
    move with no leftover resets the ramp. On phones the same two rows are
    static (`shrink-0`) inside the fixed-height preview column — see #37.

34. **Pagination splits entries, not whole sections.** `MeasureLayer` now
    measures one block per entry of a splittable section, plus a heading+first-
    entry fused block. Ids come from `getSectionPlans`/`planBlockKeys` in
    `src/lib/pagination/sectionPlans.ts` and are encoded as strings by
    `blockIds.ts` (`__entry:<section>:<entry>:<1|0>`, URI-escaped). Keeping the
    encoding a **string** preserves `pages: string[][]` for all six templates,
    `PageStack`, `PrintPortal` and the canvas-frame math — do not switch that
    contract to objects without updating every consumer. Fusing the heading
    into the first entry block is how keep-with-next is enforced: a heading can
    never be packed onto a page without its first entry. Only single-column,
    non-`keepTogether`, non-summary sections with more than one visible entry
    split; multi-column grids and `keepTogether` stay atomic. `SectionRenderer`
    decodes ids and re-groups *consecutive* entry blocks into ONE `<section>` —
    otherwise each entry gets its own page-gap and the grid columns break.
    `StudioSidebarTemplate` must route blocks by the decoded section id. The
    visibility/primary-field rules and `resolveSection` now live in
    `src/templates/shared/sectionData.ts` and are shared with the measure layer;
    keep them in sync with `atsText.ts` (see #11). `buildPackBlocks` falls back
    to a whole-section height when no entry heights were reported, which is why
    injected-measurement tests and empty sections still work.

35. **Resume prose wraps at word boundaries, not mid-word.** The `.onyx` root
    uses `overflow-wrap: break-word; word-break: normal;` — never
    `overflow-wrap: anywhere`. The latter changes min-content sizing and lets
    any word break mid-character, which shattered normal prose and bullets.
    `overflow-wrap: anywhere` is confined to the dedicated `.onyx a` rule so
    long URLs/links can still break. This is global CSS (all six templates share
    the Onyx DOM), so do not reintroduce `anywhere` on the root; `src/templates/
    onyx/onyx-css.test.ts` guards the contract by reading the raw stylesheet.
    `variants.css`/`studio.css` have no root wrap override.

36. **Fit-to-1-page has a readable floor and a visible reset.** `MIN_FIT_SCALE`
    in `src/lib/pagination/fitScale.ts` is **0.78**; `computeFitScale` returns
    `null` instead of shrinking below it, so the preview never applies
    microscopic type. `usePageLayout` reports `fitBlockedReason` (`too-tall` or
    `page-break`) and `PageOverflowBanner` renders explanatory copy in place of
    the fit button rather than a disabled control. The current applied scale
    lives in `metadata.page.fitScale`; whenever it is `< 1`, the sticky
    `[data-canvas-toolbar]` shows a **Reset fit** pill that calls `onFit(1)`.
    The whole bar (page count, Reset fit, Reset zoom) is rendered **above**
    `<TransformWrapper>`, so it can never overlap the candidate's name. Because
    it is outside the library context, zoom visibility comes from the wrapper's
    `onTransform` into React state and the reset uses the
    `ReactZoomPanPinchContentRef`; `CanvasResetButton` takes `onReset` as a prop.
    The schema still allows `fitScale` down to `0.5` so older saved documents
    load, but no new fit target is suggested below 0.78.

37. **The mobile preview is a fixed-height column with its own scroller.** At
    `< lg`, `<main>` is `flex flex-col` and `#panel-preview` is
    `flex min-h-0 flex-1 flex-col`, so the tab fills the space between the
    header and the bottom nav instead of growing with the page stack. Inside
    it, the `Visual`/`ATS text` mode header and `PreviewChrome` (overflow banner
    + page-count / Reset pills) are `shrink-0` rows, and only
    `[data-canvas-scroll]` inside `LiveCanvasViewport` scrolls
    (`min-h-0 flex-1 overflow-y-auto overscroll-contain`). The paper is
    therefore clipped at the chrome's bottom edge and can never slide behind or
    above it, and the toolbar can never scroll off-screen. Everything is
    mobile-only: `lg:block` on the panel, `lg:flex-none` on the stage/root, and
    `lg:sticky lg:top-0` / `lg:sticky lg:top-14` restore the desktop behaviour
    from #28/#33 — do not drop those variants or desktop loses its sticky
    columns. `TouchPanCanvas` only attaches its non-passive `touchmove` listener
    while `isZoomed` (mirrored from `useTransformComponent` into a prop); at the
    fitted scale there is no JS touch handler and no `scrollPageBy` hand-off, so
    native `touch-action: pan-y` scrolling is smooth instead of jittery. A
    fitted canvas is exactly as tall as its scroller, so `TransformWrapper` has
    no pan range to fight the scroll. While zoomed, `findScrollableAncestor`
    now finds that canvas box rather than `<main>`; that is the intended
    hand-off target.

38. **Drawer sheets shrink above the mobile keyboard.** `useVisualViewportOffset`
    reports the keyboard overlap as
    `max(0, innerHeight - visualViewport.height - visualViewport.offsetTop)` and
    `EntryDrawer` uses it twice: `bottom` lifts the sheet above the keyboard and
    inline `maxHeight: calc(95dvh - ${offset}px)` clamps it so a 95dvh sheet
    lifted by the keyboard cannot push its drag handle, title, and X off the top
    of the screen. Both are needed; the `bottom` lift alone overflows upward.
    The `max-h-[95dvh]` class stays as the pre-hydration fallback (the inline
    style wins once the hook measures). The sheet body and its child wrapper are
    `min-w-0 overflow-x-hidden` so a wide TipTap field or long unbroken URL
    cannot create a sideways scroll strip inside the sheet; keep those classes
    when adding section forms.

39. **Fit-to-width is applied once per fit target, never per render.**
    `react-zoom-pan-pinch`'s `useControls()` rebuilds every control closure on
    each render, so an effect that lists `setTransform` in its dependencies
    re-fits the canvas whenever it runs. `CanvasSurface` re-renders the moment
    the "zoomed" bit flips, so the first pinch frame called
    `setTransform(0, 0, fitScale, 0)` and snapped the canvas back to fit: pinch
    appeared to reset, the transform/render ping-pong jittered or froze the
    preview, and the aborted gesture left `touch-action: none` behind so the
    page would not scroll until a new touch. `useFitTransform`
    (`src/components/preview/useFitTransform.ts`) guards with a ref and only
    re-fits when `fitScale` genuinely changes (container resize, paper size, a
    new fit-to-one-page scale). Treat every `useControls()` method identity as
    unstable — never use one as an unguarded effect dependency.

40. **Blank start and Recent resumes belong to the scratch card.** `/` must keep
    exactly three named `<section>` regions (the page and e2e a11y tests count
    them), so **Start with a blank resume** and the Dexie-backed **Recent
    resumes** list render *inside* the "Start from scratch" card rather than as
    a fourth entry point. `listRecentResumes` returns `updatedAt`-descending
    rows; `renameResume` writes `basics.name` and bumps `updatedAt`;
    `deleteResume` removes the row. Labels and timestamps come from the pure
    `src/lib/store/recentResumes.ts` (name → headline → "Untitled resume").
    The preset `<ul>` carries `data-preset-list` and the e2e preset selector
    targets it, because the recent rows are also a `<ul>` of buttons. In the
    paste parser, education headers split on `| • · – —` but never on commas,
    and a school-looking value is kept whole, so
    `University of California, Berkeley` stays one school instead of becoming a
    school plus an invented location. Inline headings
    (`SKILLS: Python, SQL`) are only recognised when the heading is all caps;
    title-case `Languages: TypeScript, Python` stays a skills category inside
    the current section (it must not switch to the spoken-languages section).

41. **A re-measure must not reset the preview's scroll.** Moving a section up or
    down changes the canonical order, so `usePageLayout` returns `pages: [[]]`
    with `isMeasuring: true` for a frame. On desktop `#panel-preview` is its own
    scroller (`lg:max-h-… lg:overflow-y-auto`); the paper stack is replaced by a
    240px placeholder, the panel stops overflowing, and the browser clamps its
    `scrollTop` to 0. `usePreservedScroll` (`src/components/preview/
    usePreservedScroll.ts`) listens for scroll events in the capture phase on
    `document`, records the last offset of any ancestor scroller of the preview
    root, and restores it in a layout effect once `isMeasuring` clears. It
    ignores offsets recorded while the container has nothing to scroll
    (`scrollHeight <= clientHeight`), because that is the placeholder clamp, not
    a user scroll. Do not switch that guard back to a ref written during render:
    `react-hooks/refs` rejects it, and `react-hooks/immutability` rejects a
    cross-effect mutable scroller ref. Section reordering is the trigger; entry
    reordering keeps the same block keys and does not blank the canvas.

42. **Basics previews are local and degrade cleanly.** `BasicsForm` shows a
    `Name preview` fed by `useWatch`, so it follows every keystroke before the
    50 ms debounced `patchDoc`, and a `PicturePreview` keyed by the trimmed URL.
    A failed image flips to a `role="status"` message instead of a broken-image
    glyph. `HeaderSlot` is a client component that remembers the failed URL and
    stops rendering `AvatarSlot`, letting the header text span both grid columns;
    never render a resume-header `<img>` without that error path or a broken URL
    prints a broken-image icon.
43. **Action-verb insertions respect the preceding character.** The pure
    `actionVerbInsertion` helper in `src/lib/richtext/actionVerbs.ts` prepends a
    space only when the cursor follows non-whitespace; `RichTextField` reads
    `editor.state.selection.$from.parent.textBetween(offset - 1, offset)` and
    delegates the formatting. Keep the spacing rule unit-tested there rather than
    reimplementing it inline.

44. **Design controls reuse existing document fields.** `src/lib/design/
    designOptions.ts` owns the curated choices: six accent swatches plus the
    monochrome default, three font pairings, and three density presets. The
    Design panel writes values into fields that already drive rendering —
    accent → `metadata.design.colors.primary` (flows through `--brand-primary`),
    font pairing → `typography.body/heading.fontFamily` (the `var(--font-sans)`
    / `var(--font-serif)` locals from `layout.tsx` + `globals.css`, so offline
    and static-export safe), density → the new `design.density` enum **plus**
    `page.gapX/gapY` and `body.lineHeight`. Because `buildTemplateThemeStyle`
    and `MeasureLayer` already read those numbers, preview, measurement and
    print stay aligned without new CSS variables or a parallel renderer; a
    density change simply triggers a re-measure. Do not add a second accent
    field — `design.colors.primary` is the single source of truth, and the
    checked swatch is derived from it (case-insensitively, defaulting to
    `mono`). The `normal` preset must keep matching the Zod defaults
    (8/12/1.4) or existing documents jump spacing on load.

45. **A skills row is visible when either its category or its keywords exist.**
    Every other section still keys visibility off its primary field, but the
    skills `name` is an optional category: the paste parser emits one
    `name: ""` row for unlabeled lists (`SKILLS` → `SQL, Excel`), so filtering
    on `name` alone silently erased it from Visual Preview, measurement, and
    ATS text. The rule lives in `isVisibleItem`/`visibleItems`
    (`src/templates/shared/sectionData.ts`) and is mirrored in `atsText.ts`
    (`keywordsCountAsContent` for skills) and `isDraft`
    (`src/lib/store/selectors.ts`). Keep those three in sync (see #11/#34).
    `SkillEntry` also omits its `<h3>` when the category is blank, so a
    keyword-only row renders as pills or the comma list with no empty heading
    line. Hidden items still win: `hidden === true` hides the row regardless
    of keywords.

46. **The Studio Sidebar anchors its side column on Page 1.** Packing is a
    shared single-column sequence (`order = [...main, ...sidebar]`, see #34), so
    a tall main column pushes the short sidebar sections (`skills`, `languages`,
    `certifications`, `interests`) onto a later page whose main side is empty.
    `StudioSidebarTemplate` gathers every sidebar block id across all pages
    (decoding split entry blocks through `sectionIdOf`) and renders them in
    Page 1's `<aside>`; `pages` itself stays canonical for `atsText`, print, and
    canvas-frame math. Pages `> 0` receive only main blocks and add
    `studio-layout--full`, whose CSS collapses the grid to one column so no
    orphaned blank sidebar remains; a resume with no sidebar sections also
    renders full-width on Page 1. The measure layer is still template-agnostic
    (#32) — sidebar height is measured at full content width, not side-column
    width — so a genuinely tall sidebar can still overflow Page 1.

  `playwright.cmd`, `next.cmd`.

  and needs a real `out/` build.

  individually when you need CDP.
- In jsdom, vaul's pointer press handler throws `setPointerCapture is not a
  function`: `userEvent.type` inside a drawer and `userEvent.click` on a drawer
  child both trigger it. Use `fireEvent.change` for drawer form fields and
  `fireEvent.click` for controls such as the drawer's top-right Close button in
  component tests.
- When a test spies on a zustand action with a deferred promise, never resolve
  it after the action mutates the store: `setDoc`/`patchDoc` replace the state
  object while the spy is installed, the new object copies the mock reference,
  and `vi.restoreAllMocks()` cannot repair it — later tests then call the mock
  and never navigate. Either keep the deferred pending (assert the busy state
  only) or restore the action before any store update.

## CI and deployment

- `.github/workflows/deploy.yml` — on push to `main`: `npm ci` → typecheck →
  test → build with `PAGES_BASE_PATH` → deploy to GitHub Pages.
- `.github/workflows/opencode-autopilot.yml` — every 6 hours: one task from
  `TASKS.md` via `opencode run`, verify, commit, push, deploy. Partial work goes
  to branch `wip/opencode-checkpoint`; the next run resumes from it.
- Live at <https://darelphilipo.github.io/resume-maker/>.

### Autopilot failure modes (read before tuning the workflow)

1. **Free-tier version floor.** `opencode-ai` below **1.18.0** prints
   `Error: OpenCode 1.18.0 or newer is required to use the free tier` and stops.
   The workflow pins `1.19.5`. If the pin is ever lowered, or the free tier
   raises its floor again, this is the first thing to check.
2. **`opencode run` can exit 0 while doing nothing** — that same version gate
   exits 0. Exit codes therefore prove nothing on their own. The workflow has a
   `Fail if the agent made no changes` gate: a run that leaves the tree
   untouched fails the job. Never replace it with exit-code checks alone.
3. **Every run uploads `opencode-run-log`.** It is the only place the model's
   output is visible. Failed runs keep it too (`if: always()`).
4. **`git status --porcelain` must be empty before a run** for the no-change
   gate to mean anything; don't leave local edits to be swept into a bot commit.
5. **`GH_PAT` is optional.** With `GITHUB_TOKEN` the push cannot trigger
   `deploy.yml`, so the workflow dispatches it manually; with a PAT the push
   triggers it and the manual dispatch is skipped. Don't do both.

### 2026-11-18 — Pinch zoom stays put (fit no longer re-applies per render)
- Task: top P0 Queue item — preview "resets" on pinch, jitters/freezes when
  zooming, cannot pan a zoomed page, and page scrolling works only sometimes.
- Root cause: `FitTransform` in `LiveCanvasViewport` ran
  `setTransform(0, 0, fitScale, 0)` from an effect keyed on
  `[fitScale, setTransform]`, but `react-zoom-pan-pinch`'s `useControls()`
  rebuilds every control closure on each render. `CanvasSurface` re-renders when
  the zoomed bit flips, so the first pinch frame immediately re-fitted the
  canvas: zoom snapped back, the render/transform ping-pong produced jitter and
  freezes, and the aborted gesture left `touch-action: none` so the next swipe
  could not scroll the page. One bug, all four symptoms. Recorded as Decision
  #39.
- New `useFitTransform` applies the fit transform only when `fitScale` actually
  changes (ref guard, ignores non-finite values); `CanvasSurface` now uses it.
  No other preview behaviour changed.
- `useFitTransform.test.tsx` mocks `useControls()` with a fresh `setTransform`
  identity per render and proves an unrelated re-render does not re-fit, while a
  real `fitScale` change does. Verified the test fails (2 calls) when the guard
